# Setu — Intelligent Conversational AI for KSP Crime Database

A conversational AI and crime analytics prototype built for the KSP Hackathon
challenge: *"Intelligent Conversational AI for KSP Crime Database."*

> **Note on data**: This prototype uses a fully **synthetic, fictional crime
> dataset** (generated by `data/generate_dataset.py`) for demonstration
> purposes. No real FIRs, real persons, or real KSP records are used or
> referenced anywhere in this project.

---

## 1. Problem Statement

State police forces sit on large volumes of crime data (FIRs, accused,
victims, case status) that is hard to query without SQL/database expertise,
and even harder to mine for hidden patterns — repeat-offender networks,
hotspots, socio-demographic risk factors. Setu is a natural-language
interface over crime records that also surfaces network, trend, and
risk-scoring insights an investigator can act on immediately.

## 2. What this prototype does

Scoped to what's achievable and demo-able as a 6-day prototype (see
**Roadmap** below for the full vision):

## 3. Architecture

```
┌─────────────────────────┐        ┌──────────────────────────────┐
│   client/index.html     │        │   Zoho Catalyst (deployment)  │
│   - Chat UI (EN/KN)      │  HTTP  │   ┌────────────────────────┐ │
│   - Network graph (vis.js)│──────▶│   │ chatQuery Function      │ │
│   - Trend dashboard       │◀──────│   │ (Python Advanced I/O)   │ │
│   - PDF export (jsPDF)    │        │   │  -> engine.py (RAG +    │ │
└─────────────────────────┘        │   │     retrieval + LLM)    │ │
                                     │   └───────────┬────────────┘ │
                                     │               ▼               │
                                     │   Data Store (ZCQL) /         │
                                     │   demo: local JSON in data/   │
                                     └──────────────────────────────┘
                                               │
                                               ▼
                                   Anthropic API (api.anthropic.com)
                                   grounded, cited natural-language answers
```

**Design principle**: the same `engine.py` runs locally (via `server.py`,
a thin Flask wrapper) and in Catalyst (via `handler.py`, the Catalyst
Advanced I/O wrapper). This means everything you test locally behaves
identically once deployed — only the request/response plumbing differs.

## 4. Tech stack

- **Backend**: Python 3.12, Catalyst Advanced I/O Functions
- **Data**: JSON seed dataset (demo) → designed to map 1:1 onto Catalyst
  Data Store (ZCQL) tables in production (see §7)
- **LLM**: Anthropic Claude API (`claude-sonnet-4-6`) for grounded,
  citation-required answers; falls back to an offline templated response
  if no API key is set, so the demo works without any external dependency
- **Frontend**: Vanilla HTML/CSS/JS (no build step) — Catalyst Web Hosting
- **Libraries**: [vis-network](https://visjs.github.io/vis-network/) (network
  graph), [Chart.js](https://www.chartjs.org/) (dashboard charts),
  [jsPDF](https://github.com/parallax/jsPDF) (conversation export)
- **Fonts**: IBM Plex Sans / IBM Plex Mono / Noto Sans Kannada

## 6. Local setup & execution (test before deploying)

```bash
# 1. Clone
git clone <this-repo-url>
cd ksp-crime-ai

# 2. Generate the synthetic dataset (only needed once, already included in repo)
cd data && python3 generate_dataset.py && cd ..

# 3. Install backend deps
pip install -r functions/chatQuery/../../requirements.txt
#   (i.e. pip install flask flask-cors)

# 4. (Optional) Enable real LLM answers
export ANTHROPIC_API_KEY=sk-ant-...
#   Without this, the app runs in "offline demo mode": it still retrieves
#   and displays the correct records, just without LLM-composed prose.

# 5. Run the backend
cd functions/chatQuery
python3 server.py
#   Serving at http://localhost:5000

# 6. Open the frontend
#   Just open client/index.html directly in a browser (double-click it,
#   or `python3 -m http.server 8000` from the client/ folder and visit
#   http://localhost:8000). It already points at http://localhost:5000.
```

Try asking:
- "Show me chain snatching cases in Indiranagar"
- "Which cases are still under investigation?"
- Switch the language dropdown to ಕನ್ನಡ and ask again
- Go to **Network Analysis** → "Load repeat-offender network"
- Go to **Offender Risk Scoring** → "Load top offenders"

## 7. Deploying to Zoho Catalyst

1. Install the Catalyst CLI and log in:
   ```bash
   npm install -g zcatalyst-cli
   catalyst login
   ```
2. From the project root, initialize/link the Catalyst project:
   ```bash
   catalyst init
   ```
   Choose **Functions** (Advanced I/O, Python 3.12) and point it at
   `functions/chatQuery`, and **Client (Web Hosting)** pointed at `client/`.
3. In the Catalyst Console, go to **Functions → chatQuery → Environment
   Variables** and add `ANTHROPIC_API_KEY`.
4. Deploy:
   ```bash
   catalyst deploy
   ```
5. Copy the function's live execution URL from the Console (**Functions →
   chatQuery → Domain**) and update the `API_BASE` constant near the top of
   the `<script>` block in `client/index.html` to point at it instead of
   `http://localhost:5000`.
6. Re-deploy the client (`catalyst deploy` again, or just the client
   component) and grab the Web Hosting URL — that's your submission's
   **Deployed Solution Link**.

**Moving from demo JSON to Catalyst Data Store (production path):** replace
the `_load()` calls at the top of `engine.py` with ZCQL queries, e.g.
`zcql.executeQuery("SELECT * FROM FIRS WHERE crime_type = ?")`, against
tables you create in **Catalyst Console → Data Store** using the same
column names as the JSON fields in `data/data_seed/*.json`. The rest of
`engine.py` (retrieval, network, dashboard, risk scoring) needs no changes
since it consumes plain Python dicts either way.

## 8. Explainability & responsible-AI notes

- Every chat answer is required (via the system prompt) to cite FIR IDs and
  is generated only from retrieved records — not from the model's general
  knowledge — reducing hallucination risk for an investigative tool.
- The offender risk score is a **transparent weighted scorecard** (prior
  convictions, case frequency, crime-type diversity, recency), not an
  opaque ML model, and always returns its component breakdown.
- Known limitation to disclose to evaluators: predictive/hotspot features
  in the full vision carry real feedback-loop bias risk (over-policing an
  area inflates its recorded crime, reinforcing the prediction) — any
  production forecasting module should include periodic bias audits
  against actual outcomes, which is out of scope for this prototype.
